- Confirmed `@vscode/test-electron`'s harness runs inside a real Extension Development Host, so `vscode.window.showInputBox`/`showQuickPick`/`showWarningMessage` are plain mutable object properties on the `vscode` module and can be monkey-patched per-test (queue up canned responses, restore the originals in `teardown`) — this is how interactive command handlers (that take no other testable seam) get exercised end-to-end without a mocking library. - New Windows-only test-authoring gotcha: `fs.rmSync(tmpDir, { recursive: true, force: true })` in a test's `teardown` can intermittently throw `ENOTEMPTY` right after `squadRegistry.dispose()` because a just-disposed `FileSystemWatcher`'s native handle isn't always released synchronously on Windows. Fix: add `maxRetries`/`retryDelay` to that `rmSync` call (Node's built-in retry for exactly this class of transient Windows file-lock error) — cheaper and more reliable than an artificial `setTimeout` before cleanup.
- This session's shared working tree was unusually hot: uncommitted WIP diffs appeared/disappeared across multiple production files (`squadRegistry.ts`, `squadChatParticipant.ts`, `dashboardPanel.ts`) and untracked WIP test files referencing not-yet-added exports from other concurrent agents, and `node_modules/.bin` was transiently emptied mid-session by another agent's concurrent `npm install`. Recovery playbook that worked: (1) only run `npm install` myself once a missing `node_modules/.bin` has clearly stalled (not mid-copy) — restoring dependencies is in-scope when validation fails due to missing tooling; (2) temporarily rename other agents' non-compiling in-flight test files aside (`*.wip-hold`) rather than deleting them; (3) `git stash push -- <specific file>` to shelve just the one breaking production-file WIP diff long enough for a clean compile/test, then `git stash pop` immediately after — never a bare `git stash` (that would also shelve untracked new files' *sibling* tracked changes unpredictably); (4) always restore every held-aside/stashed file before staging anything; (5) `git add <specific paths>` only, never `-A`/`.`.
